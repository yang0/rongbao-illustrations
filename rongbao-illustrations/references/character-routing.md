# 角色选择规则

角色选择由 [character-registry.json](character-registry.json) 驱动，默认角色是 `rongbao`（绒宝）。角色选择与正文/组合画幅路由分开：先解析角色，再把选中的角色资产和身份参考传给当前执行面。

## 选择顺序

1. 没有识别到角色名称或别名：使用默认绒宝。
2. 识别到中文或英文别名：选择对应角色；英文别名不区分大小写，例如 `yazai`、`YAZAI` 和 `YaZaI` 都选择牙仔。
3. 同一请求识别到绒宝和牙仔：两名角色都保留身份并参与核心动作，可以同图出现。
4. “这个IP”“该IP”是泛指，不切换角色；没有具体识别名时仍使用默认绒宝。
5. 只有用户明确使用“使用/切换到/指定某某 IP”等语义点名一个未注册名称时，才返回当前支持列表并请求用户改用支持名称；普通正文中的陌生名词不触发该错误。

## 确定性解析入口

解析完整用户请求时，先解析当前 Skill 根目录，再运行：

```text
python -X utf8 <skill-root>/scripts/character_router.py --json "<request>"
```

普通文章正文中出现陌生名词时，不加 `--explicit`；没有已知别名就按默认角色处理，不把普通名词误报为未知 IP。只有用户明确使用“使用/切换到/指定某某 IP”等语义点名角色时，才在上述命令末尾加 `--explicit`，让未注册名称返回支持列表和错误。

## 透传与资产

每个选中角色都读取其注册的 `asset` 和 `identity_reference`。原生正文模式将角色身份套入正文规则；组合模式将每个角色的参考图传给目标设计 Skill，目标 Skill 决定媒介表现。若同时选择两名角色，不能只传一张参考图或只保留一名角色的身份。

角色资产、身份参考或注册项缺失时，doctor 报告角色状态；strict 模式失败，不能静默退回绒宝。
