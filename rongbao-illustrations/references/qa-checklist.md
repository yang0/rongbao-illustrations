# QA Checklist

## 必过项

- 如果本次实际生图或改图，已运行角色路由器并读取 `character_inputs`；每个已选 `asset_path` 都经过 `view_image`，且所有这些路径按注册表顺序传入 `referenced_image_paths`。
- 生图提示词明确标注 `Image 1/2/3` 与每个显示名的对应关系，并说明每张图仅作为对应角色的身份参考；没有只依赖文字身份描述，也没有附加未选角色图片。
- 如果本次只是 `prompt`、shot list 或路由计划，未无谓加载图片，但计划展示了运行时解析出的绝对 `asset_path` 和角色映射。
- 如果走可选 IP Illustration Character System：有注册角色/IP 信号时为 `mode=upstream` 并注入已选角色；只有能力词或直接上游调用且无信号时为 `mode=direct-target` 且不注入；普通文章配图仍为 `native`。
- 如果走 Baoyu：文章配图/封面/信息图使用选中角色原图作为 direct reference；漫画原图优先于衍生角色表；slide deck 只在内容合适的页面出现角色；xhs-images 要求所有选中角色原图用于第一张生成，第一张生成成品才成为后续链式 anchor。Baoyu 不套用 GPT Image 2 门禁。
- 可选上游输入顺序为角色图 → style_ref_01 → style_ref_02 →（未选牙仔）style_ref_03 →（仅信息图）layout refs；没有附加未选 IP 或非本次能力的 layout 图。
- Everett 上游实际直生图前明确确认 GPT Image 2；未知/通用图像工具只交付 prompt package 和官方 GPT Image 2 链接。Baoyu 不套用此门禁。
- 是 16:9 横版。
- 背景是干净白底。
- 有已选择的角色，并保留各自身份协议锚点；未指定角色时默认检查牙仔的黑白拟人猫、黑色尖耳/头顶毛块、半眯竖瞳、宽扁脸、两颗门牙、胡须、长卷尾、白衬衫、黑马甲或黑领结和围裙。若选择绒宝，检查其黄色圆形主体、青绿色叶耳、棕黑大眼、橙色腮红和橙色手脚；若选择阿龅，检查其黑白拟人犬、下垂黑耳、头顶毛、长口鼻/黑鼻头、门牙和白衬衫加深色工装。
- 每个已选择角色都承担核心动作，不只是装饰。
- 多角色时每个角色身份彼此独立，不出现混合角色、借用其他角色的脸型或让某个角色只露出无身份的局部。
- 没有复刻旧案例构图，而是为当前文章生成了新隐喻。
- 画面怪诞、有创意、有意思。
- 简洁清爽，主体不超过画面约 60%。
- 一张图只讲一个核心结构。
- 中文标注少、短、能读。
- 橙色只用于主路径或箭头。
- 红色只用于重点、问题、提醒或结果。
- 蓝色只用于补充说明、反馈或系统状态。

## 失败信号

出现以下情况，重生成或局部编辑：

- 左上角有“常见坑 / Workflow / 系统架构图 / 路线图”等标题。
- 已选择角色像参考图的摄影/渲染材质、表情包或过度可爱的吉祥物。
- 实际生图/改图没有调用 `view_image`，没有将全部已选 `asset_path` 传入 `referenced_image_paths`，或 Image 标签与角色映射不一致。
- 附加了未选角色的参考图，或从开发机硬编码路径读取图片。
- 可选上游缺失时静默假装已安装、自动复制上游代码/图片，或把可选依赖的正常 missing 状态当作 strict 错误。
- style_ref_03 在选中牙仔时仍被附加，或 layout refs 在非 3:4 信息图能力中出现。
- Everett 未显式确认 GPT Image 2 却直接生图，或用通用图像工具替代。
- Baoyu 漫画把衍生角色表当成注册原图的替代，slide deck 强迫每页出现角色，或 xhs-images 没有把所有选中原图传给首张生成，或误把原图当作后续 chain anchor。
- 已选择角色丢失其身份协议锚点；若选择绒宝，重点检查黄色主体、青绿色叶耳、棕黑大眼和橙色四肢；若选择牙仔或阿龅，分别检查对应黑白猫/犬身份和服饰锚点。
- 背景复制了任一角色参考图的米色、渐变、阴影或摄影棚质感。
- 画面像 PPT、课程课件、正式流程图。
- 元素太多、箭头太多、节点太多。
- 文字变成大段解释。
- 背景有纸纹、阴影、渐变、米色、噪点。
- 真实 UI 截图或科技感界面。
- 中文错字严重或标注不可读。
- 画面太死板，没有荒诞隐喻。
- 和 `assets/examples/` 里的旧案例构图过于相似。

## 迭代方法

- 太普通：让每个已选择角色成为动作主体，加入一个奇怪但成立的隐喻。
- 太复杂：删节点，只保留一个动作和 3-5 个短标注。
- 太可爱：保留已选择角色身份锚点，但强调简洁手绘、克制表情、not 3D furry、not mascot。
- 太 PPT：去掉标题、边框、整齐网格和过多箭头，改成手绘场景。
- 太像旧案例：保留核心意思，换掉主物件和角色动作。
- 文字错：优先局部编辑；错得多就重生成并减少标注数量。

## 交付判断

高质量图应该让读者先觉得“有点怪”，然后 1 秒内看懂结构。

如果第一眼像教程页，而不是白纸上的怪诞产品草图，就不合格。
